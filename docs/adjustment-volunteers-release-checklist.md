# 调剂补录自动匹配上线清单

## 变更范围

- 仅 GPSS 应用；半山学堂服务不变。
- 仅遴选阶段未录取且符合周期/专业资格的学生可填补录志愿。
- 学生可按顺序选择 1–6 个已发布、课题名额未满且教师总指导名额未满的本专业课题；不限制覆盖教师数量。
- 学生可在截止前修改志愿。截止时间到达后由系统统一自动匹配，不经过教师遴选；匹配依学生志愿顺序、课题名额和教师总名额完成。
- 同一教师课题竞争按周期、教师、学生 ID 生成的 SHA-256 排序值决定先后，排序版本记录为 `sha256-teacher-priority-v1`。匹配结果保存在现有结算记录和操作日志中，可重复核对。
- 保留旧 `adjustments` 表与记录，旧调剂写入/教师逐条审批接口返回 `410`，历史查询只读。

## 上线前备份与基线

1. 通过既有 GPSS 部署脚本备份 MySQL 数据库和上传目录，记录备份目录、生成时间与校验值。
2. 保存当前周期配置及准确截止时间：

```sql
SELECT id, name, status, phase, phases_config
FROM cycles
WHERE status IN ('active','selection','review','adjustment');
```

3. 保存首次遴选录取和课题容量基线：

```sql
SELECT a.status, COUNT(*) AS records
FROM applications a JOIN topics t ON t.id = a.topic_id
WHERE t.cycle_id = :cycle_id
GROUP BY a.status;

SELECT t.id, t.title, t.teacher_id, t.max_students,
       SUM(a.status = 'accepted') AS accepted_count
FROM topics t LEFT JOIN applications a ON a.topic_id = t.id
WHERE t.cycle_id = :cycle_id
GROUP BY t.id, t.title, t.teacher_id, t.max_students;
```

4. 确认周期处于调剂阶段，`phases_config.adjustment.end` 为有效时间；学生只可在该截止时间之前提交/修改志愿。

## 发布后核对

1. 查看容器启动日志，确认数据库初始化和现有迁移成功。
2. 检查 `/api/health` 及管理员调剂结算页；结算页应显示资格学生、志愿人数、自动录取数、未匹配人数、课题容量和截止时间。
3. 学生账号核对仅显示本专业已发布且同时有课题名额、教师总名额的课题；可提交 1–6 个志愿，无教师覆盖数提示；截止前可修改。
4. 教师账号核对调剂页仅说明系统按学生志愿自动匹配，不提供逐人遴选、退回或录取操作。
5. 管理员账号核对截止前不能触发正式结算；截止后系统自动运行，失败时管理员只能重试失败的结算。
6. 结算完成后核对每名学生最多新增一个录取、课题和教师容量均未超额；已录取学生保留原结果；未匹配学生有明确状态；操作日志及学生、教师、管理员通知存在。
7. 不在生产周期手动运行结算来模拟验收；以隔离数据验证匹配边界和并发情况。

## 回滚

- 页面或 API 异常：通过既有部署流程回退 GPSS 源码或镜像；保留已有调剂表结构和数据。
- 自动结算已写入而结果异常：暂停调剂流程，先保存结算记录和操作日志，再使用同次发布前数据库备份恢复；不要再次运行结算覆盖结果。
- 上传目录异常：恢复同一次发布前上传目录备份。
- 回滚后复核健康接口、当前周期、首次遴选状态和录取人数。

## 隔离验收场景

覆盖 1 个和 6 个志愿、0 个和 7 个志愿拒绝、无需教师覆盖、专业/资格限制、已录取学生锁定、课题名额耗尽、教师总名额耗尽、同课题竞争及稳定排序、首选满额后递补次选、截止前等待、截止后自动结算、失败后管理员重试、重复运行幂等、事务回滚和通知/日志。生产数据不用于模拟故障。
