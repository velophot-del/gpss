# 毕业材料模板驱动实施计划

**目标：** 管理员上传的 DOCX 是任务书、开题、中期材料的唯一生成来源；学生填写区与管理员确认的映射一致，固定内容和阶段计划保持原样。

**架构：** 解析 DOCX 正文段落与表格，提出字段映射，管理员确认后发布。新增配置及材料绑定表保存文件哈希、映射快照与扩展填写值；绑定版本一旦使用，不随新版发布变化。沿用 Vue、Express、MySQL、PizZip，不新增依赖。

**依据：** 本会话用户确认的模板识别、固定/填写区域、版本绑定及禁止静默回退方案。

## 约束和判断

- 保留上传原件；固定区在导出中不重写。复杂结构无法安全处理时拒绝发布，不猜测。
- 使用普通段落范围映射，管理员可修改标签、填写来源和范围；未映射部分是固定内容。手写签名区保留。
- 历史记录不自动绑定新版；管理员可明确选择未绑定的历史材料关联模板，操作不更改其原始填写内容。
- 在当前干净工作区实施以便现有演示服务加载；不提交、推送或部署正式环境。
- DOCX 的固定 XML/样式资源可校验；长内容的分页、Word 桌面显示另列验证边界。

## 任务

- [ ] 1. 增加模板识别/渲染回归测试，验证封面旧题目清除、具体要求完整替换、年份不变、未知栏目及损坏文件被阻止。
- [ ] 2. 实现段落映射、配置校验与保持原包资源的填充；保护固定文字、签名、日期及其他包文件。
- [ ] 3. 增加幂等建表迁移、管理员识别/确认/预览接口、不可变发布配置与删除引用保护。
- [ ] 4. 接入学生保存、教师查看和导出：服务器选定版本，事务内绑定，固定字段不可由学生覆盖，未绑定历史记录需管理员明确关联。
- [ ] 5. 管理员提供映射确认界面；学生与教师共用模板内容组件，任务书计划只读。
- [ ] 6. 构建、全量回归与独立演示库 HTTP 验证；检查模板原件哈希与导出固定区，不擅自发布用户草稿。

## 重点验证

- 发布新版、归档旧版及删除操作不能改变已绑定材料。
- 伪造 templateId、固定值或其他学生记录不得绕过权限与校验。
- 多段正文替换不能残留示例内容，也不能清空签名区。
- 缺文件、哈希不符、无已确认版本时明确报错，无内置模板兜底。
- 模板栏目变更必须反映到填写表单；无需填写的固定栏目不再被旧规则强制要求。
