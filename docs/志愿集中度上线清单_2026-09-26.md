# 志愿集中度功能上线清单（2026-09-26）

## 发布范围与现状

- 发布包：`release/gpss-concentration-20260926.tar.gz`；同名 `.sha256` 为校验文件。包顶层只有 `gpss-src/`，保留当前工作树的 GPSS 源码，不含本地 `.env`、种子数据、上传文件、构建结果、浏览器资料和学生手册。
- 线上已登录页面仍为旧版；第一志愿提示、管理员集中度页、当前周期监控尚未上线。发布前后均不得把旧页面的“人数”解释成已录取人数。
- 本包包含当前工作树此前已修改的 GPSS 页面和接口，涉及工作台、学生选题与调剂、教师审核、管理员监控；上线审核应以整个包为单位。构建会使用线上原有环境变量及数据库。
- 不使用现有 `deployment/upgrade-gpss.sh`：它会替换 `/opt/banshan-academy` 并重建、重启 `banshan-app`，超出本次 GPSS 上线范围。`deployment/docs/统一部署升级.md` 中“只重建 gpss-app”的描述与该脚本不一致。

## 上线前确认

1. 确认服务器仍采用 `/opt/banshan-academy/deployment/unified/docker-compose.yml`、`/opt/gpss-src`、`gpss-app` 和 MySQL `gpss` 库；确认管理员有 Docker 权限。若实际路径或编排不同，先调整步骤。
2. 在服务器本地校验发布包 SHA-256 和成员路径；检查包内没有 `.env`、`node_modules`、`uploads`、`seed-data`。
3. 备份 `gpss` 数据库、`/opt/gpss/uploads`、`/opt/gpss/uploads-private` 和旧 `/opt/gpss-src`。确认备份非空且可读。
4. 在教师和学生知悉的短维护窗口操作。仅重建并替换 `gpss-app`；启动时 `entrypoint.sh` 会运行幂等数据库初始化和流程迁移。上线前核对当前数据库迁移状态。

## GPSS 单服务替换顺序

以下为操作顺序，不应照搬未核实的环境变量或目录。保持旧容器运行，先在服务器将包解压到独立暂存目录并检查源码。将 `/opt/gpss-src` 重命名为带时间戳的备份目录，再把暂存的 `gpss-src` 移入 `/opt/gpss-src`。在统一编排目录运行 `docker compose config`、`docker compose build gpss-app`、`docker compose up -d --no-deps gpss-app`。不得运行 `docker compose down -v`，也无需重建 `banshan-app`、MySQL、Nginx。

发布后核对容器健康状态和日志、`/gpss/api/health`、学生课题列表第一志愿人数、学生提交前集中提醒、管理员“学生选课状态”页的当前周期集中度。核对课题第一志愿人数与申请表中 `priority=1` 的当前周期有效申请数一致；导师第一志愿按学生去重。导出匿名集中度 CSV，不公开学生名单。

如 GPSS 服务检查失败，保留新源码目录并将旧源码目录恢复到 `/opt/gpss-src`，重建、重启 `gpss-app`，再核对健康状态。数据库迁移可能已执行，不能仅凭更换源码推断数据库已回滚；需要结合备份和迁移日志判断是否恢复数据库。保留完整操作日志和备份位置。

## 业务发布顺序

1. GPSS 上线且页面核验通过后，发布学生说明和教师说明；通知稿见 [执行记录](志愿集中度执行记录_2026-09-26.md)。公开文案由学院核准。
2. 管理员在填报期每日导出匿名集中度，按课题第一志愿/名额、导师第一志愿去重人数/指导上限看趋势；对未填报学生按学院本届名单核对后再定向提醒。
3. 不在本届中途改变已提交志愿的有效性或增设硬性封禁。调剂排序标准须学院确认后公告。
