# 半山学堂统一部署升级（GPSS 源码包）

适用于：阿里云服务器上以 **Docker Compose 单机编排 + Nginx 反向代理** 方式部署
「半山学堂 + 毕业设计管理系统（GPSS）」的升级场景（`banshan-academy/deployment/unified/`）。
GPSS 经 `/gpss/` 子路径嵌入，Nginx 剥除 `/gpss/` 前缀转发到 `gpss-app:3011`。

## 拓扑

```
/opt/
├── banshan-academy/deployment/unified/   # 统一编排(docker-compose.yml + nginx.conf)
└── 20260823_学生教师体验改版/            # GPSS 源码(gpss-app 的 docker build context)
```

- 容器：`gpss-app`(3011) + `banshan-gpss-mysql`(共享 MySQL) + `banshan-nginx`
- 数据卷：`/opt/banshan/mysql`(数据库)、`/opt/gpss/uploads`(上传文件)、`/opt/gpss/uploads-private`(私有模板)
- 升级只重建 `gpss-app` 一个镜像，MySQL / Nginx / banshan-app 不受影响

## 源码包

| 项 | 值 |
|---|---|
| 包文件 | `gpss-upgrade-<日期>.tar.gz` |
| 顶层结构 | `gpss-upgrade-<日期>/`（内含 `20260823_学生教师体验改版/` 与 `banshan-academy/` 两个兄弟目录，与 compose build context 一致） |
| 包内排除 | `node_modules`、`dist`、`.git`、真实 `.env`（含密钥）、`uploads`/`uploads-private`/`seed-data`（数据）、`release`、`qa`、日志 |
| 包内保留 | 全部 `.env.example`、`server/src/assets/process-templates/*.docx`、`deployment/aliyun/Dockerfile`+`entrypoint.sh`、`deployment/unified/` 全套、`deployment/docs/` 升级文档 |

> 打包命令见 `scripts/export-upgrade-package.sh`（输出到两个项目的父目录并打印 sha256）。**重新导出后必须重新计算 sha256 并更新本节。**

### 校验

权威校验文件是包外的 `gpss-upgrade-<日期>.tar.gz.sha256`（`scripts/export-upgrade-package.sh` 每次打包自动生成）。上传到服务器后校验：

```bash
shasum -a 256 -c gpss-upgrade-<日期>.tar.gz.sha256   # 输出 ... OK 即通过
```

> 包内嵌入的文档副本里也有一份校验值，但会因「文档含在包内、包内文档又记录包校验值」这一循环而比最新包落后一位，**请以包外的 `.sha256` 文件为准**。

## ⚠️ 私有模板目录持久化（升级必看）

GPSS 新版把「已发布的正式文档模板」存放在 uploads 的兄弟目录 `/data/uploads-private`（位于公共
静态服务之外，防止被 `/uploads` 暴露）。该目录**必须作为卷持久化**，否则容器重建后已发布模板会丢失。

`gpss-app` 的 volumes 必须包含两行：

```yaml
    volumes:
      - /opt/gpss/uploads:/data/uploads
      - /opt/gpss/uploads-private:/data/uploads-private   # 私有模板持久化
```

包内三份 compose（`deployment/aliyun/docker-compose.yml`、`deployment/compose.yaml`、
`banshan-academy/deployment/unified/docker-compose.yml`）均已包含。升级时用包内 compose 覆盖服务器旧版即可。

新版首次启动会自动把旧的 `/data/uploads/private-templates` 迁移到 `/data/uploads-private`（幂等，仅在目标目录不存在时执行）。

## 升级步骤

### 1. 备份（必做，不可跳过）

```bash
cd /opt/banshan-academy/deployment/unified
mkdir -p /opt/gpss/backup

docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --no-tablespaces --single-transaction --routines --triggers gpss' \
  | gzip > /opt/gpss/backup/gpss-$(date +%Y%m%d-%H%M%S).sql.gz

tar -czf /opt/gpss/backup/uploads-$(date +%Y%m%d-%H%M%S).tar.gz -C /opt/gpss/uploads .

cp -a /opt/20260823_学生教师体验改版 /opt/20260823_学生教师体验改版.bak-$(date +%Y%m%d)
cp -a /opt/banshan-academy /opt/banshan-academy.bak-$(date +%Y%m%d)
```

### 2. 传包并解压（目录名必须与 compose build context 一致）

```bash
# 开发机
scp gpss-upgrade-<日期>.tar.gz 用户@服务器IP:/tmp/

# 服务器：先 shasum -a 256 校验，再覆盖解压（--strip-components=1 去掉外层目录）
cd /opt && rm -rf 20260823_学生教师体验改版 banshan-academy \
  && tar -xzf /tmp/gpss-upgrade-<日期>.tar.gz -C /opt --strip-components=1
```

> 包内不含 `.env`，服务器上 `deployment/unified/.env` 的真实配置（数据库密码、JWT 密钥）**不会被覆盖**。

### 3. 确认配置后重建并重启

```bash
cd /opt/banshan-academy/deployment/unified
docker compose config | grep -A6 "gpss-app"     # 确认 build.context 指向 /opt/20260823_学生教师体验改版
docker compose build gpss-app
docker compose up -d gpss-app
```

容器启动时 entrypoint 自动执行（均幂等，不会重复造管理员/演示数据）：

1. `node dist/scripts/initDb.js` —— 建表
2. `node dist/scripts/migrateAddProcessStages.js` —— 扩展 `cycles.phase` 枚举 + 创建全流程表
3. `node dist/scripts/bootstrapAdmin.js` —— 仅当无管理员时创建

### 4. 验证

```bash
docker compose ps
curl -I http://127.0.0.1/gpss/api/health          # 期望 200
docker compose logs --tail=100 gpss-app            # 重点检查迁移是否有报错
```

浏览器访问 `http://<服务器IP>/gpss/`，用 admin 登录后抽查：选题周期、任务书填写/审核、
开题/中期审核、正式 Word 导出、公告。


## 注意事项

- 升级上线的是**当前工作区源码**（git 可能有未提交改动），先确认要发布的内容。
- 历史 `issued` 状态的任务书在新版中**不可再编辑/确认**（新版仅接受 `submitted`/`need_revision`）。
  若线上存在 `issued` 任务书，升级前需评估（手动改状态或接受现状）。
- 生产环境 `ENABLE_DEMO_LOGIN` 必须为 `false`，`PUBLIC_BASE_PATH=/gpss` 必须生效（否则上传文件 URL 缺前缀、图片会挂）。
- 数据卷（`/opt/banshan/mysql`、`/opt/gpss/uploads`、`/opt/gpss/uploads-private`）**不要删除**，备份也请保留。
